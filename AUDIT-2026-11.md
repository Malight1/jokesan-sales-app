# ProfixBook full app audit (21 November 2026)

This covers every page in the app. For each page it says what was wrong, what was fixed in this pass, and what is still left. It started from the client's complaints: team invites, suppliers, customers, quotes and getting paid.

**Status key:** Fixed = done in this pass. Needs work = found, not fixed yet. OK = no real problem found.

---

## 1. What you must do before these fixes go live

The app code is ready, but these steps have to be done first. Until steps 1 and 2 are done, the new join links will show "We couldn't open this invite".

1. **Run the database change.** In Supabase, open SQL Editor and run `supabase/migrations/0053_invite_links_supplier_bank.sql`. It adds the invite lookup, the safe "claim invite" step, and bank detail columns on suppliers. It changes no existing data.
2. **Deploy the new function `accept-invite`.** Edge Functions → New function → name it exactly `accept-invite` → paste `supabase/functions/accept-invite/index.ts` → **turn OFF "Enforce JWT verification"**. It has to accept calls from people who don't have an account yet. There are no secrets to set.
3. **Set up email so invites are actually emailed** (Supabase's built-in sender only delivers to your own Supabase team members, 2 an hour, so real staff never get anything):
   - Create a free account at resend.com and add **profixbook.com** as a domain. Resend shows a few DNS records; add them where profixbook.com's DNS is managed, then wait for "Verified".
   - In Resend, create an API key. In Supabase → Project Settings → Edge Functions → Secrets, add `RESEND_API_KEY` with that key. (`ticket-notify` uses the same key, so support emails start working too.)
   - Replace the code of the existing `invite-teammate` function with the new `supabase/functions/invite-teammate/index.ts` and deploy (keep JWT verification ON).
   - Also in Supabase → Authentication → Emails → SMTP Settings, turn on custom SMTP with Resend's details (host `smtp.resend.com`, port 465, user `resend`, password = the API key, sender `info@profixbook.com`). That fixes sign-up confirmations and password resets, which use Supabase's own mailer.
4. **Push the frontend.** It deploys from `main` as usual.

Until step 3 is done, inviting still works: the invite box says "The email did not send" and you tap **Send on WhatsApp**.

For the client who is stuck right now: once steps 1, 2 and 4 are done (email can come later), open Settings → Team → Pending Invites, tap **Share link** on abdulwakeelkesington@gmail.com, and send it on WhatsApp. They tap it, choose a password and they're in.

## 2. The client's complaints, and what happened

### "Invite team is not working, it is trash"
**Cause.** Invites depended on Supabase sending an email. That email wasn't going out (Supabase's built-in sender is rate-limited and restricted). The fallback copied a message telling the person to "sign up". Sign-up asks for a *company name* (so it looks like you're creating a new business), and then *also* needs an email confirmation that never arrives. So the invitee tried **Sign In** instead and got "Invalid login credentials". No path actually worked.

**Fixed.**
- An invite now creates a **join link** (`/join/<code>`) and **emails it automatically** through Resend (`invite-teammate`, rewritten). The "Send the join link" box shows what really happened: **Email sent** (only when the email service accepted it) or **The email did not send**, with the reason and a Try again button. It never claims an email went out when it didn't.
- The same box has **Send on WhatsApp** (opens WhatsApp with the message and link already written; you pick the staff member and tap send), Copy link, and Copy full message for SMS.
- Inviting someone who already has a pending invite now re-sends their link instead of stopping with "There is already a pending invite".
- The invitee opens the link, sees "Join *Business* as *Sales staff*", types their name and a password, and is signed straight in. Joining needs no confirmation email, so it works even when email doesn't (new `accept-invite` function + `JoinTeam.tsx`).
- It is safe. The link is a random code only your admins can see. It works once. It can never reset the password of someone who has already signed in, and it never moves an email that belongs to another business.
- If the person had already half-signed-up with that email, the link still works and finishes the job.
- Pending invites have a **Share link** button to resend the same link.
- Sign In now explains itself instead of "Invalid login credentials": *"That email and password don't match an account… If you were invited, open the invite link you were sent to set your password first."*
- Create Account now says up front: *"This creates a new business. Joining someone else's business? Open the invite link they sent you instead."*
- Show/hide eye on password fields (phone typos were locking people out).

### "Supplier is poorly done. It shows we are owing, but not what to pay"
**Fixed.**
- Suppliers page now opens with **You owe suppliers ₦X** and **Suppliers owe you ₦Y**.
- Each row: **You owe them ₦X** with a **Pay** button right next to it, plus their bank account ("Pay into").
- Tapping a supplier opens their **account**: what you owe, what you've bought, what you've paid, **their bank account with a Copy button**, and every unpaid purchase with its own **Pay** button. Pay records the payment against that purchase.
- Supplier form now has **Their bank account** (bank, account number, account name). It needs migration 0053.
- WhatsApp and Call buttons to reach the supplier.

### "Creating a quote, there is nowhere to put the account number the person pays to"
**Cause.** Bank details existed but were buried in Settings → Business, labelled "printed on a proforma invoice only". So a normal quote never showed them, and the quote form never mentioned them.

**Fixed.**
- The quote form has a **Where the customer pays** section showing your bank account. An admin can add or change it right there.
- Bank details now print on **both** quotes and proformas.
- The WhatsApp quote message now lists the items, VAT, total, valid-until date, terms **and how to pay**.
- Quote vs Proforma is now two clear choices with a one-line explanation of each, not a bare dropdown.
- "Valid until" defaults to 14 days. Expired quotes show an **Expired** badge.
- New actions: Customer accepted, Customer declined, Turn into a sale. The quote view has PDF, WhatsApp and Turn into a sale buttons.
- Turning a quote into a sale no longer defaults to "on credit" with the full amount paid (that contradicted itself). It now defaults to Transfer/Cash, and "Not paid yet (on credit)" is an explicit choice that says how much the customer will owe.
- Product lines are a proper grid, so columns line up and labels aren't repeated on every row.
- The page's styles were missing (it borrowed styles that only existed on Sales). It now has its own stylesheet.

### "How is customer money managed? How do you send the customer something so they can pay?"
**Cause.** Reminders said "your balance is ₦X, kindly settle" with **no account number and no link**. The Customers page didn't show who owed anything.

**Fixed.**
- **Every money message now ends with how to pay.** That covers debt reminders (Dashboard, Retail dashboard, Reports → Debtors), WhatsApp receipts with a balance (Sales and the till), quotes, and pay-link messages. Your bank name, account number and account name are included, and so is a Paystack pay link when Paystack is connected.
- **Customers page** now opens with **Customers owe you ₦X**, store credit held, and the account customers pay into. Each row shows **Owes you ₦X** with a **Collect** button, plus when they last bought.
- Tapping a customer opens their **account**: what they owe, what they've bought, store credit, every unpaid invoice (with how old it is), and:
  - **Send payment request**: a WhatsApp message listing each unpaid invoice, the total and your bank details.
  - **Record payment**: per invoice, when money comes in.
  - **Pay link**: per invoice, when Paystack is connected. It creates a Paystack link and sends it on WhatsApp, and the invoice marks itself paid when they pay.
  - Call button, and a warning (with a link to fix it) if your bank account isn't saved.
- Settings → Payments now gives the **actual webhook URL with a Copy button** and explains you must paste it into Paystack. Without that step, pay links never mark invoices paid. Before this, the page showed a developer note about "the payments-webhook Edge Function's URL from your Supabase project", which a customer could never act on.

### "Please explain these two parts and what is till" (Settings → Business)
**Fixed** by rewriting the labels so they explain themselves:
- Returns setting is now *"Can cashiers take back goods and refund customers?"*, with plain options and a line explaining what a return does.
- Till setting is now *"Make staff open the till before selling"*, with an explanation of what a till is and what opening and closing it means. The old text told single-shop owners to set up tills "under Branches", but single-shop accounts don't even have a Branches tab. It now says "Your shop already has one till ready".
- Bank details are now labelled *"Bank account customers pay into"* and say where they're shown.

### The pricing page looked broken (raw grey boxes)
**Cause.** Form fields only got styled inside a `.form-group` wrapper. Any field outside one fell back to the browser's raw look. That happened on the price list box, the price list dropdowns, team role dropdowns and others across the app.

**Fixed.**
- Every text field, dropdown and text box in the whole app now gets the proper style by default, with a consistent dropdown arrow. This fixes every page that had raw fields, not just Pricing.
- Pricing tab redesigned: a proper header, an "Add" button with a label, clearer wording ("Normal price", "Prices on Wholesale"), and the developer note removed (*"can be set per product in the database already, this screen sets one flat price per list for now"*).
- Settings tabs now scroll sideways on phones (they were cut off at "Billin…").
